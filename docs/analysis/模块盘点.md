## 模块明细

### `app/hello_app`

- **职责**：注册并执行一个 NSH 内置命令。
- **入口**：`main()`。
- **依赖**：NuttX Apps、`stdio`、Kconfig、Make/CMake 应用注册接口。
- **问题**：队伍编号和配置符号散落；无领域接口、错误路径与测试。
- **去向**：替换为产品应用目录，按事件、策略、Agent、Tool、UI、存储拆分。

### `board/contest_board`

- **职责**：提供板级初始化占位入口。
- **入口**：`openvela_board_initialize()`。
- **依赖**：NuttX Board API、板级 Kconfig 与 defconfig。
- **问题**：明确不可启动真实硬件；不能代替 ESP32-S3-EYE BSP。
- **去向**：默认不纳入产品；仅在确需板级修改且按公共仓 PR 流程时使用。

### `quickapp/hello_quickapp`

- **职责**：渲染单页问候界面。
- **依赖**：QuickApp Runtime、UX DSL、应用 manifest。
- **问题**：缺少 `/common/logo.png`；无事件处理；并非 AI 硬件方向的必要路径。
- **去向**：仅在端端协作或手机/配套界面能显著加分时保留。

### `logs`

- **职责**：保存可审计的 AI Coding 会话。
- **接口**：`logs/<github_login>/manifest.json` 与不可修改的 JSONL 会话。
- **问题**：当前仍是 team 000 示例；真实采集只在能识别 `.repo/` 的工作区内激活。
- **去向**：Phase 1 安装并验证采集器；每阶段审查隐私后持续提交。

### Repo manifests

- **职责**：声明完整 openvela 工作区并将参赛模块映射进编译树。
- **数据流**：manifest -> 项目检出 -> linkfile -> 构建树。
- **优点**：队伍 manifest 边界清晰，新增模块只需稳定目录和映射契约。
- **问题**：当前实际工作树与 manifest 声明不一致；必须先恢复完整性。

## 目标模块边界

| 目标模块 | 单一职责 | 端口契约 |
|:---|:---|:---|
| `domain/events` | 定义标准化设备与时间事件 | 可序列化事件结构 |
| `domain/policy` | 本地阈值、状态机和主动策略 | 事件输入、动作意图输出 |
| `agent/router` | 连接 ai_agent Router/Skill | 意图与上下文结构 |
| `tools` | 执行白名单设备动作 | Tool 请求/结果结构 |
| `adapters/sensors` | 读取摄像头、音频、加速度计 | 标准事件 |
| `adapters/cloud` | LLM/ASR/消息服务适配 | 可替换请求/响应 |
| `ui` | LVGL 状态与反馈 | 只消费视图模型 |
| `storage` | 轻量记忆与任务持久化 | 版本化记录格式 |
| `diagnostics` | 指标、审计与故障信息 | 结构化统计快照 |
