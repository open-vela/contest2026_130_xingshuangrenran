# 高分开发任务分解

## 总览

- **阶段数**：6
- **任务数**：29
- **总体工作量**：XL
- **策略**：先恢复可复现真机基线，再锁定产品；先纵向打通主动闭环，再增加多模态和高级能力；最后以可靠性与评分证据收口。
- **跟踪方式**：LOCAL_ONLY。本轮不创建 GitHub Issue/Milestone/Project。

## 全局约束

- 所有功能必须绑定自动化测试或最接近的静态/真机验收；文档任务需执行链接和 Markdown 检查。
- 每项完成时同步保存构建命令、日志、指标、截图/视频和评分项映射。
- 所有稳定命令、硬件限制和架构决策更新到 `docs/progress/总进度.md`。
- 每个任务均须通过其 S.U.P.E.R 驱动原则的 Quick Check。
- 不覆盖 repo-managed 参赛仓已有未提交改动，不修改公共仓内容后直接混入专属仓。
