## 代码目录与编译树映射

| 参赛仓源码目录 | openvela 编译树位置 |
|:---|:---|

## 构建流程

构建命令只在 openvela 工作区根目录执行：

```bash
cd /Users/xingranya/Downloads/GitHub-clone/openvela-workspace

./build.sh <board-config-path> [menuconfig|distclean] [-j8]
```

T1.3 已补齐 `packages/ai_agent` 与 `vendor/espressif`。当前确认存在两条官方配置路径：板卡全功能基线使用 `vendor/espressif/boards/esp32s3/esp32s3-eye/configs/openvela`，ai_agent 使用 `esp32s3-eye:ai_agent` 与 `packages/ai_agent/fix_esp32s3.sh`。

macOS 统一入口位于参赛仓 `scripts/`：

```bash
cd /Users/xingranya/Downloads/GitHub-clone/openvela-workspace/contest2026_130_xingshuangrenran

./scripts/检查开发环境.sh
./scripts/构建固件.sh openvela --clean
./scripts/构建固件.sh ai_agent --clean
./scripts/烧录固件.sh
./scripts/串口监视.sh
```

其中构建脚本仍调用工作区根目录官方 `build.sh`，只负责 macOS 的 PATH、并发数、defconfig 和串口设备名适配。官方命令与替换关系见[官方教程合规清单](./官方教程合规清单.md)。

## AI Coding 日志

比赛日志采集器通过工作区根目录的 `.repo/` 判断是否属于比赛开发。使用 AI 工具时，应从以下目录或其子目录启动：

```bash
cd /Users/xingranya/Downloads/GitHub-clone/openvela-workspace/contest2026_130_xingshuangrenran
```

日志最终归集到参赛仓的 `logs/<github_login>/`。独立 clone 不在 `.repo/` 目录树内，不能作为正式日志采集入口。

## Repo 更新与提交边界

- openvela 公共项目继续由工作区根目录的 Repo manifest 管理。
- 参赛代码只提交到 `contest2026_130_xingshuangrenran` 专属仓。
- 修改 `nuttx`、`vendor_espressif` 等公共仓时，按官方要求向对应仓的 `dev-ai-contest-2026` 分支提交 PR，不把公共仓改动复制进专属仓。
- 执行工作区更新前先检查各项目未提交状态，保护本地修改；禁止使用会丢失改动的强制覆盖操作。
