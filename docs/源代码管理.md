## 官方提交模型

依据官方《参赛代码提交指南》，比赛期间采用：

```text
官方专属仓 dev-ai-contest-2026
        ↓ fork
个人 fork 的功能分支
        ↓ Pull Request
官方专属仓 dev-ai-contest-2026
        ↓ 自行 review 并合入
```

远端命名固定为：

| 远端 | 指向 | 用途 |
|:---|:---|:---|
| `openvela` | `open-vela/contest2026_130_xingshuangrenran` | 官方专属仓，只作为上游与 PR 目标 |
| `fork` | `xingranya/contest2026_130_xingshuangrenran` | 个人 fork，功能分支的 Push 目标 |

当前本地开发分支：

```text
feat/esp32s3-eye-baseline-20260712
```

该分支基于 `openvela/dev-ai-contest-2026` 的提交 `1294cdf` 创建。个人 fork 已创建并配置为 `fork` 远端；作品未完成真机验证前不创建 PR。

## 公共项目修改

修改 `nuttx`、`apps`、`packages/ai_agent` 等公共项目时，不得复制进参赛专属仓或直接 Push 到官方仓库。每个公共项目需要单独 fork，并向其 `dev-ai-contest-2026` 分支提交 PR，由组委会 review。

当前构建过程涉及的公共项目修改包括：

- `packages/ai_agent/fix_esp32s3.sh`：修复 `/data` tmpfs 匹配失败仍报告成功的问题。
- `nuttx/boards/xtensa/esp32s3/esp32s3-eye/src/esp32s3_bringup.c`：实际挂载 `/data` tmpfs。
- `apps/crypto/mbedtls/Make.defs`：官方 ESP32-S3 修复脚本生成的头文件优先级适配。

这些改动后续分别评审、提交，不与参赛仓 commit 混合。

## 禁止事项

- 不在 `openvela-workspace` 根目录执行 `git pull`。
- 不在停用的独立 clone 中继续开发。
- 不在工作区和独立 clone 之间手工双向复制源码。
- 不向 `openvela` 远端直接 Push 功能分支。
- 不提交 API Key、Wi-Fi 密码、私钥或 `.env` 文件。
- 不忽略或删除最终需要提交的 `logs/` AI Coding 日志。
