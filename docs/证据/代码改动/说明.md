# 公共仓代码改动说明（联网稳定性与语音唤醒）

本目录汇总本作品对 openvela **公共仓**（`packages/ai_agent`、`nuttx`）的源码改动。按大赛规则，公共仓改动不写入参赛仓本体，此处仅作**可复现证据**留存：完整补丁、涉及文件与复现方式。所有补丁均不含 Wi-Fi 密码、MiMo Key 或火山凭据。

## 改动范围

| 补丁 | 目标公共仓 | 文件数 | 主题 |
| --- | --- | ---: | --- |
| [packages_ai_agent.patch](./packages_ai_agent.patch) | `packages/ai_agent` | 4 | 语音唤醒词、Wi-Fi 重连自愈、TLS 诊断、板级网络配置 |
| [nuttx_net.patch](./nuttx_net.patch) | `nuttx` | 4 | 网络栈联网判定放宽 |

## packages/ai_agent 改动明细

- **`src/voice/voice_channel.c`** — 语音唤醒词闸门（对应阶段四 T4.2）。
  在 ASR 结果分发前校验识别文本是否包含规定唤醒词「你好，openvela」（`strcasestr` 匹配 `openvela` / `open vela`）；未命中则忽略该轮语音，命中后取唤醒词之后的正文送入 Agent，正文为空时以「你好」占位。
- **`src/infra/network_manager.c`** — Wi-Fi 关联重试与掉线自愈。
  连接流程改写为最多三轮的重试循环：`ifdown`/`ifup` 复位驱动、`wapi` 配置模式/PSK/ESSID、以 `SIOCGIWAP` 轮询 BSSID 判定**真实关联**（而非盲等固定时长），关联后清空静态 IP 再 `renew` 走 DHCP；新增监控线程每 5 秒复查关联状态，掉线即触发重连。
- **`src/infra/vela_tls.c`** — TLS 握手诊断。
  在 `net_connect` / `ssl_setup` / `ssl_handshake` 失败处打印真实 mbedTLS 错误码（如 `-0x52` DNS 解析失败、`-0x4c` 接收失败），便于定位联网链路问题；移除一处可能触发服务端 RST 的最大分片长度设置。
- **`defconfigs/esp32s3-eye/esp32s3-eye_defconfig`** — 板级网络配置。
  默认 DNS 由不可达的 `10.0.0.1` 改为 `223.5.5.5` 并配置双 nameserver；`CONFIG_IOB_NBUFFERS` 由 64 提升至 256、`CONFIG_IOB_THROTTLE` 提升至 24、启用 `CONFIG_NET_TCP_WINDOW_SCALE`，改善握手期缓冲与吞吐。

## nuttx 改动明细

- **`net/netdev/netdev_findbyaddr.c`、`net/netdev/netdev_default.c`** — 路由查找的接口可用性判定由 `IFF_IS_RUNNING`（要求 carrier）放宽为 `IFF_IS_UP`，避免关联建立瞬间的路由查找失败。
- **`net/udp/udp_sendto_buffered.c`、`net/udp/udp_sendto_unbuffered.c`** — 同步放宽 UDP 发送路径的接口判定，避免 DHCP/UDP 首包被误判 `EHOSTUNREACH`。

## 复现方式

在与 openvela `dev-ai-contest-2026` 基线一致的工作区内：

```bash
# packages/ai_agent
cd packages/ai_agent
git apply --check <本目录>/packages_ai_agent.patch
git apply <本目录>/packages_ai_agent.patch

# nuttx 网络栈
cd ../../nuttx
git apply --check <本目录>/nuttx_net.patch
git apply <本目录>/nuttx_net.patch
```

随后在工作区根目录按 `scripts/构建固件.sh` 重新构建，产物为 `nuttx/nuttx.bin`。

## 安全声明

两个补丁仅含源码与板级 Kconfig 文本，**不含**任何 Wi-Fi SSID/密码、MiMo Key、火山 AppID/Token 或 Tavily Key；运行期凭据一律通过串口 `set_*` 命令注入 `/data`，不进入源码与仓库。
