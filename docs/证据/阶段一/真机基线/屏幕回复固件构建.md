# ESP32-S3-EYE 屏幕回复固件构建记录

## 结论

- 已为 ESP32-S3-EYE 新增独立的 240×240 LVGL UI 通道。
- UI 使用官方板级产生的 `/dev/fb0`，由独立线程初始化 LVGL 并执行 `lv_timer_handler()`。
- CLI、WebSocket、语音和远端渠道产生的 AI 回复会镜像到屏幕。
- 已启用 SimSun 16 CJK 内置字体，可显示中文；常见 Markdown 标题、强调和代码标记会在设备端做轻量清理。
- 摄像头视觉 Tool、中文屏幕 UI 和 MiMo 回复链已同时通过 clean build 和最终链接。
- 本记录只证明源码、配置和链接闭环；LCD 真机显示、刷新稳定性和长文本效果仍需烧录验证。

## 架构边界

现有 `src/ui/lvgl_ui_channel.c` 面向已有系统 LVGL 事件循环的 466×466
手表设备。本轮没有修改该实现，而是新增：

```text
src/ui/lvgl_ui_channel_esp32s3.c
```

ESP32-S3-EYE 路径如下：

```text
AI Agent outbound message
  -> lvgl_ui_channel_send()
  -> 线程安全的最新回复缓冲
  -> ESP32-S3-EYE UI 线程
  -> LVGL 240×240 回复视图
  -> /dev/fb0
  -> ST7789 LCD
```

所有 LVGL 控件创建和更新都在 UI 所属线程执行，其他线程不直接调用
LVGL，从而避免渲染期间跨线程修改控件。

## 最终配置

```text
CONFIG_AI_AGENT_CAMERA=y
CONFIG_AI_AGENT_LVGL_UI=y
CONFIG_GRAPHICS_LVGL=y
CONFIG_LV_FONT_SIMSUN_16_CJK=y
CONFIG_LV_FONT_DEFAULT_SIMSUN_16_CJK=y
CONFIG_LV_USE_NUTTX=y
CONFIG_VIDEO_FB=y
CONFIG_ESP32S3_CAM=y
CONFIG_LIB_JPEG_TURBO=y
```

`CONFIG_LV_USE_NUTTX_LCD` 未启用，因此 LVGL 使用 framebuffer 驱动和
默认 `/dev/fb0`，与当前 ai_agent 板级 bring-up 保持一致。

## macOS 构建兼容修复

LVGL 上游同时包含：

```text
tests/Makefile
tests/makefile/
```

macOS 默认大小写不敏感文件系统无法同时表示两条路径，会把
`tests/Makefile` 识别成目录。构建适配现在仅在该路径是普通文件时包含
LVGL 单测 Makefile；固件未启用 `CONFIG_LVGL_UNITTESTS`，因此不会损失
目标功能。

同时修正了比赛仓构建封装：增量构建不再主动删除 HAL；仅在 clean build
或 HAL 缺失时通过官方 `distclean` 恢复一致状态。

## 测试边界

当前没有可在 macOS 主机直接运行 NuttX framebuffer 和 LVGL 生命周期的
自动化测试面，因此本轮使用以下最接近验证：

1. `git diff --check`；
2. 构建脚本 `bash -n` 与 dry-run；
3. ESP32-S3-EYE 完整 clean build；
4. 最终配置和 ELF 符号核对；
5. 固件尺寸与 SHA-256 记录。

运行时验收必须在真机完成，不能以编译成功替代。
