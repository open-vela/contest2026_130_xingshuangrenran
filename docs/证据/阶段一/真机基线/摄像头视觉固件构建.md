# ESP32-S3-EYE 摄像头视觉固件构建记录

## 结论

- 已在 `esp32s3-eye:ai_agent` 目标中启用 ESP32-S3-EYE 官方摄像头板级实现。
- 已将 `/dev/video0` 的 `320×240 RGB565` 帧通过 V4L2 USERPTR 采集，并接入 `libjpeg-turbo` 软件 JPEG 编码。
- 已完成最终链接，ELF 中同时存在摄像头采集、JPEG 转换、Tool 入口和 Xtensa `setjmp/longjmp` 符号。
- 本记录只证明编译与链接闭环；摄像头真机取帧、MiMo 视觉回答和 LCD 显示仍需烧录后验证。

## 板级与配置

最终 `.config` 包含：

```text
CONFIG_ARCH_SETJMP_H=y
CONFIG_ARCH_BOARD_CUSTOM=y
CONFIG_ESP32S3_CAM=y
CONFIG_ESP32S3_EYE_LCD=y
CONFIG_VIDEO_STREAM=y
CONFIG_LIB_JPEG_TURBO=y
CONFIG_AI_AGENT_CAMERA=y
```

自定义板级目录为：

```text
../vendor/espressif/boards/esp32s3/esp32s3-eye
```

## 实现路径

ESP32-S3-EYE 摄像头路径如下：

```text
/dev/video0
  -> V4L2 USERPTR 双缓冲
  -> 320×240 RGB565
  -> 逐行 RGB888 转换
  -> libjpeg-turbo，质量 75
  -> llm_chat_vision_raw()
  -> MiMo v2.5 视觉回答
```

逐行转换只额外分配一行 `320×3` 字节缓冲，避免再分配完整 RGB888 帧。

## 构建链修复

本轮依次修复：

1. NuttX Makefile 未把 `tool_camera.c` 加入 `libapps.a`；
2. Make/CMake 缺少 `libjpeg-turbo` 头文件目录；
3. Xtensa libc 未启用 `setjmp/longjmp` 实现；
4. `libjpeg-turbo/jcphuff.c` 的局部变量 `BR` 与 Xtensa 寄存器宏冲突；
5. HAL 重新克隆后需要恢复 `SP_UNLOCKED` 与 mbedTLS CCM 兼容补丁。
