## 失败与根因

第一次 clean build 失败于：

```text
packages/ai_agent/src/tools/tool_media.c:30:10:
fatal error: media_player.h: No such file or directory
```

赛事 manifest 包含以下三个项目，但当时本地目录缺失：

```text
frameworks/multimedia
frameworks/multimedia/media
frameworks/multimedia/media/pfw
```

通过定向 `repo sync -c -j1 --fail-fast` 恢复后，`media_player.h` 和 `media_policy.h` 均存在，后续构建成功。

## 官方修复脚本校正

`packages/ai_agent/fix_esp32s3.sh` 原脚本的 Python 匹配串会把 C 源码中的 `\n` 解释为真实换行，导致 `/data` tmpfs 补丁匹配失败但仍打印成功。现已改用 raw string，并在匹配失败时返回非零；板级文件已实际包含：

```c
nx_mount(NULL, "/data", "tmpfs", 0, NULL);
```

该修改位于公共 `packages/ai_agent` 项目，后续需按比赛规则单独提交上游 PR，不混入参赛专属仓提交。

## 待跟踪警告

- `build/envsetup.sh` 在 macOS 上调用不存在的 `lsb_release`，会输出宿主检测警告，但未影响配置、编译和镜像生成。
- ESP32-S3 Wi-Fi 适配层出现 `nxsem_post`、`task_tls_*` 隐式声明警告；当前不是构建阻断项，但需结合真机 Wi-Fi 烟测判断是否存在运行时风险。
- `agent_loop.c` 的提醒回复存在 `snprintf` 可能截断警告，后续主动提醒功能开发时应修正并补边界测试。
